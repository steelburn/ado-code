# ADO Code 0.8.0 — release promo kit

Everything needed to announce **0.8.0** (released 2026-10-28). Copy is derived from the
`[0.8.0]` section of `CHANGELOG.md`; if that changes, update this file in the same commit.

**The one-line pitch:** ADO Code turns Azure DevOps work items into a governed documentation
factory that runs inside VS Code — and now the AI can build the whole document set itself.

**Who it is for:** business analysts, technical writers and testers who deliver against work
items — plus the engineers who are asked to maintain "the docs folder".

---

## 1. Marketplace blurb (short — store listing / sidebar)

> **ADO Code 0.8.0 — documentation that ships with the work item.**
> Three role templates (Business Analysis, IT Documentation, Test & UAT) scaffold requirements,
> design, test and UAT documents wired to one `REQ / TC / EX / EVD` identifier vocabulary, with
> Word, Excel and PNG export straight from the chat panel. Ask the assistant to build the project
> for you — `list_doc_templates` shows what a template contains, `build_documentation` scaffolds it
> into your workspace in one guarded call. Optional **KRiSA** governance mode adds the compliance
> matrix, change control and security evidence a government delivery review asks for.

## 2. Marketplace blurb (long form — blog / dev.to / LinkedIn article intro)

> Most AI coding assistants stop at code. ADO Code starts from the work item, and 0.8.0 pushes the
> same discipline into documentation.
>
> Pick a role template and the extension scaffolds a real documentation project: numbered
> requirements, design, user and test documents, joinable registers, and traceability from
> requirement to test case to executed evidence. A project is a working definition of done, not a
> folder of empty stubs — every file opens with its section headings and a digest header telling
> the reader what the document answers.
>
> New in 0.8.0:
>
> - **The assistant can build the project.** `list_doc_templates` enumerates the templates and
>   their files; `build_documentation` scaffolds the chosen one into the workspace — path-confined,
>   and it refuses to overwrite a non-empty folder unless you explicitly ask.
> - **Export without leaving the chat.** Word, Excel, and PNG diagrams from the chat panel, with
>   exports and Mermaid diagrams rasterised reliably (0.8.0 also fixes exported diagrams losing their
>   labels and "Export diagram" always failing).
> - **KRiSA (government) governance mode** for teams that must evidence compliance, change control
>   and security, not just deliver.
> - **Context discipline you can see.** Everything the assistant generates — artifacts, skills,
>   `AGENTS.md` blocks, repository understanding — now carries a visible context cost and a hard
>   budget, so long sessions stay coherent instead of silently blowing the window.
> - **Quieter chat.** Fold tool cards with one item in the ⋮ menu, and a turn's consecutive tool
>   calls collapse into a single "Ran N tools" row.

## 5. Publish checklist

```bash
npm run check:version      # package.json == src/shared/version.ts
npm run vscode:prepublish  # compile + bundle
npx vsce package           # -> ado-code-0.8.0.vsix
npx vsce publish           # VS Code Marketplace (VSCE_PAT)
npm run publish:open-vsx   # Open VSX (OVSX_PAT)
```

Post-publish: confirm the live version on both marketplaces shows `0.8.0`, and keep the packaged
`ado-code-0.8.0.vsix` for manual installs.

## 6. Don't say

- Don't claim a template "writes your documentation for you" — it scaffolds structure and the
  assistant fills it in with you reviewing.
- Don't promise KRiSA certification — the mode produces the evidence set, not an endorsement.
- Don't quote context-budget numbers that are not in `README.md` or the settings table.
