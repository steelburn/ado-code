# ADO Code 0.8.1 — release promo kit

Everything needed to announce **0.8.1** (released 2026-10-28). Copy is derived from the
`[0.8.1]` section of `CHANGELOG.md` and `docs/remote.md`; if either changes, update this file
in the same commit.

**The one-line pitch:** ADO Code now puts your running agents in your pocket — a phone-sized
console that mirrors every run on this machine, so you can leave the desk without losing sight
of a long job.

**Who it is for:** anyone who starts a long agent run and then walks away from the keyboard —
developers, BAs and technical writers who want to know *when* a run needs them, not just
*that* it finished. It is a second screen for the machine, not a remote control for it.

**The honest headline:** this is **oversight**, not operation. Phase 1 shows you what is
happening and tells you when a consent prompt is waiting. It does not let the phone approve
tools or type instructions. Say that plainly — it is the feature, not a gap.

## 2. Marketplace blurb (long form — blog / dev.to / LinkedIn article intro)

> **Long agent runs have an attention problem.** You start a multi-file task, watch the first
> few tool calls, and then go do something else — and the moment the run needs you (a consent
> prompt, a failure, a result worth reading) is exactly the moment you are not looking at the
> screen.
>
> **0.8.1 answers that with a second screen.** Remote Agent Oversight serves a small web console
> from ADO Code itself. One status bar item — `Remote`, or `Remote 2` when two devices are
> watching — turns the listener on and off, and a QR panel shows the URL, the reachability of
> that URL, and a one-line explanation of *how* this device can get to it.
>
> The console is a mirror, not a cockpit. It lists the agent runs active on the machine, streams
> their status and results as they happen, and surfaces the consent prompts that are waiting on
> the person at the keyboard. In phase 1 it deliberately does not accept approvals or take
> instructions: the machine stays in charge, and the phone stays informed.
>
> **It is built to be safe by default.** The feature ships off. The server binds to loopback
> (`127.0.0.1`), and reaching it from another device is an explicit second step — a
> `cloudflared` quick tunnel, or a tunnel command of your own whose public URL is scraped from
> its output (pinnable with a regex), or opening the port to the LAN on purpose. Access is a
> 256-bit token carried in the URL fragment, so it never appears in a request line or a server
> log; rotating it invalidates old bookmarks by design. Every `adoCode.remote.*` setting is
> `machine`-scoped, so enabling it on a synced settings profile will not silently open a port on
> your other machines.
>
> **If you have ever come back to a finished run and wished you had known twenty minutes
> earlier:** this is that twenty minutes.

## 6. Don't say

- **Don't call it remote control, remote access *to* the agent, or a way to approve tools from
  your phone.** Phase 1 is read-only oversight. Approving tools and typing instructions are not
  in this release.
- **Don't imply it is exposed to the internet by default.** The default bind is loopback;
  tunnels and LAN access are opt-in and separately configured.
- **Don't quote the token as anything other than "in the URL fragment".** Do not describe it as
  a header, a cookie, or a login — it is a fragment, and that is why it stays out of logs.
- **Don't say the setting follows you between machines.** The `adoCode.remote.*` settings are
  `machine`-scoped on purpose; say "per machine" when asked.
- **Don't promise mobile apps, notifications, or push.** There is a web console and a QR code.
  Nothing is installed on the phone.
- **Don't present uptime or latency numbers.** None are published in `README.md` or
  `docs/remote.md`; inventing them here would outlive this file.
